# Aether 正式宿主停机分发修复

日期：2026-10-07。需求来自 Aether 第一阶段正式管线与基本退出；用户已授权 Runtime 修复。仅 Debug，不安装全局 Runtime，不修改系统接口/路由，不改变业务评分或停止期限。

## 问题与实现边界

`RuntimeShutdownCoordinator` 原循环每次注册表变化都向全部未退出单元发送 Stop/Wakeup。命令处理与状态更新又产生变化，构成反复投递。Aether 第十九轮实际 CLI 观察到序号超过 122571；该现象不能单独证明所有业务收尾失败都由它引起。

本次在单个停机操作内，分别记录每个单元成功投递的 Stop 与 Wakeup。已投递的指令不随状态变化重复发送，队列满等未投递结果仍在后续循环重试。注册表在停机开始后拒绝新注册，禁止同操作内复用单元 ID，因此记录不需要额外注册代。载荷在操作开始时一次生成。

保留注册表原首次广播及协调器首次成功投递（各一次），不改变外部显式广播 API。原首次截止期限、调用方取消仅取消等待、真实注销门槛均不变。未退出单元超时返回 124，注册信息继续保留；不会强制注销来制造成功。

## 有界验证

- Diagnostics 功能项目 Debug/x64 构建：0 警告、0 错误。
- `shutdown-contract` 独立子进程通过：首次请求/截止期限所有权、并发单请求、调用方取消、终态禁止新注册，以及新增状态更新不反复投递、满队列恢复投递和真实超时保留 owner。
- 首次满队列夹具错误按 8 项填充，而真实原子 inbox 容量为 64；该轮失败只在夹具检查，未作为通过。现改为最多 256 次有界尝试直到拒绝，复验通过。
- Aether Debug/x64 全方案构建：0 错误、12 警告；受影响生命周期/配置回归 24 项通过，含四次独立全局停止、末次生产消费完成及真实线程注销。

现场候选验证和剩余业务问题由 Aether 当日正式双宿主记录维护。本地通过不等于正式 Service 正常退出、LAN NAT 或全部网关验收完成。
