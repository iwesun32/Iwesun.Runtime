# 槽位属性与审核

## 五类属性

所有可比较属性属于以下一种类别：

- Space：坐标、尺寸、边距、对齐和布局空间。
- Style：颜色、字体、边框和常规视觉样式。
- Effect：变换、透明、动画、滤镜和三维效果。
- Action：点击等交互动作。
- DataOrganization：父子、兄弟、标识和数据组织关系。

公共泛型基础为 `ElementSlottedProperty<TValue>`。五个抽象分类基类不能直接实例化；
具体属性必须覆盖 `Audit`，因此不存在“声明需要审核但没有比较实现”的空壳。

## 同名属性的双端槽位

一个属性对象同时保存源端和 XAML 端三个槽位：

| 端 | 初始化槽位 | 链接描述 | 运行槽位 | 值来源 |
| --- | --- | --- | --- | --- |
| HTML | HTML/CSS 初始化值 | CSS、URL、表达式或其他符号描述 | DOM 渲染绝对值 | `SourceValueSource` |
| XAML | XAML 初始化值 | Binding、资源或运行时计算描述 | WinUI 渲染绝对值 | `XamlValueSource` |

链接使用不可变描述，不假设它是内存指针。泛型值既可为 `int`、`double`，也可为 `Point`、
颜色、枚举或业务定义的不可变结构。

两个值来源都使用同一强类型枚举：容器自动布局、链接计算、链接常量或直接常量。
两端分别校验；例如 XAML 运行时 Binding 必须写入 `XamlLink` 和 `XamlValueSource`，
不能仅因为 HTML 端来自 CSS 就推断 XAML 端也已实现。

## 属性特性

`ElementPropertyAttribute` 描述属性值种类、阶段、坐标模式、参考空间、轴、单位、翻译方式、
比较方式、继承方式、目标属性和允许误差。反射读取器缓存元数据并提供 `IsXXX` 分类器。

类型固有值、初始化相对值和运行时绝对值必须使用不同阶段描述，不能只按属性名称猜测。

## 审核过程

具体属性的 `Audit` 分别返回静态初始化阶段和运行阶段结果。典型数值属性使用允许误差：

- 在误差内：通过。
- 有对应值但超出误差：直接不通过。
- 目标语言确实没有对应合同：记录为人工复核。
- 不适用：明确记录，不得当作通过值参与统计。

`SlottedElementAuditor` 遍历元素属性并调用每个属性自己的审核，不重新实现属性算法。
`ElementAuditStatisticsAccumulator` 累加总数、通过数、不一致数、缺失映射数和人工复核数；
文本报告只负责说明，不得改变结构化判定。

元素公开 `Audit()` 自动审核整棵子树。顺序固定为后序遍历：容器先递归审核全部直接和间接
子元素，最后审核容器自身属性。这样子控件失败会先形成精确 XPath 报告，再汇总到父容器和
整树统计。`ElementAuditNodeReport` 保留与元素树相同的 `ChildReports → OwnReport` 层次，
并同时保存具体类自己的 `TypeReport`。每级 `Passed` 都是全部儿子、类型审核和自身属性审核的
合取结果；“无法翻译”只是属性状态，不存在独立旁路审核器。
