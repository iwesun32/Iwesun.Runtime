# 安全审计报告

> 状态说明：本文保留审计时的问题清单和验收建议，不作为当前安装包完成状态。1.0.22 的权威状态见 WEBVIEW2_RELEASE_STATUS.md；未勾选条目属于历史审计或宿主特定验证，不表示公共 Runtime 发布缺失。

## 1. 审计范围

本报告审计 `Iwesun.Runtime.WebView2` 的业务逻辑安全性，重点检查：

- 生命周期是否一致；
- 任务、事件和浏览器资源是否可靠释放；
- 初始化失败是否正确回滚；
- 停止失败是否影响其他对象退出；
- 运行状态是否与实际任务一致；
- 新旧公共接口是否安全迁移。

本文所称“安全”不指网络攻击防护，而是防止代码破坏业务流程、遗留后台任务、产生重复执行、报告错误状态或导致宿主无法正常退出。

## 2. 当前结论

项目自身及整个 Runtime 解决方案均已完成 Debug、Release 构建，结果为 0 警告、0 错误。协议统一、模块划分和编译依赖基本成立，但当前仍存在生命周期与清理方面的缺陷，不建议在修正和回归测试前作为最终版本发布。

## 3. 高风险问题

### 3.1 Ambient 输入停止后不能重新启动

当前第一次启动会把 `_started` 设置为 1；停止时取消任务，但不会恢复 `_started`。第二次启动发现 `_started` 已经为 1 后直接返回，不会重新创建鼠标和键盘任务。

可能结果：

- CLI 返回已经启动；
- 状态对象显示已启动；
- 实际鼠标和键盘循环不存在；
- 业务根据错误状态继续执行。

修改要求：

- 使用 `Stopped / Starting / Running / Stopping / Faulted / Disposed` 单一状态机；
- 每次重新启动创建新的 `CancellationTokenSource` 和任务；
- 启动、停止返回真实状态；
- 分别记录鼠标和键盘任务状态及异常。

### 3.2 多个 Program 初始化到一半失败时资源泄漏

例如 Program A、B 初始化成功，Program C 初始化失败。当前流程只撤销 Program 注册，不会对已经初始化成功的 A、B 执行停止清理。

可能结果：

- 登记表已经清空，但后台任务仍然运行；
- 浏览器、事件或文件资源仍被占用；
- 再次初始化产生重复任务和重复事件订阅。

修改要求：

- 记录已经初始化成功的 Program；
- 后续初始化失败时按反向顺序停止已初始化项；
- 单个回滚失败不能阻断其他回滚；
- 汇总初始化错误和清理错误；
- Host 最终状态设置为 `Faulted`。

### 3.3 一个 Program 停止失败会阻断其他 Program 退出

当前停止流程中，任意 Program 的 `StopAsync` 抛出异常后，后续 Program 不再停止，Host 状态和登记清理也可能无法完成。

可能结果：

- 部分 Program 已停止，部分仍在运行；
- Program 登记无法完全撤销；
- Host 仍显示 Active；
- Runtime 安全退出等待超时。

修改要求：

- 每个 Program 的停止操作互相隔离；
- 一个停止失败后继续停止其余 Program；
- 所有停止动作结束后统一汇总错误；
- 无论业务停止是否成功，都继续执行活动任务取消、登记撤销和状态更新；
- 最终状态区分 `Stopped / StoppedWithErrors / TimedOut`。

## 4. 中风险问题

### 4.1 生命周期存在绕过统一锁的入口

`WebRuntimeProgramHost` 使用生命周期锁，但 `WebRuntimeProgramCommandTarget` 仍可直接调用 Registry 的初始化和停止方法。CLI 命令可能与宿主激活或退出并发，导致重复初始化、重复停止或状态错乱。

修改要求：所有初始化和停止入口统一经过 Host，由 Host 维护状态和串行化。

### 4.2 Ambient Controller 重复释放不安全

`DisposeAsync` 没有幂等保护。第二次释放可能再次操作已经释放的 `CancellationTokenSource`。

修改要求：增加原子 disposed 标志；重复释放直接返回；释放后禁止启动。

### 4.3 后台输入任务异常后仍显示运行

鼠标或键盘 pulse 抛出普通异常后，循环任务会结束，但当前状态仍可能保持 `IsStarted=true`、`IsStopped=false`。

修改要求：任务异常时转为 `Faulted`，保存错误摘要，并通过 Runtime 监视点发布状态变化。

### 4.4 旧公共接口已按破坏性迁移计划废止

旧 `IWebRuntimeControl` 已删除并由 `IWebRuntimeSession`、`RuntimeDiagnosticFrame`、`IWebRuntimeBusinessProgram` 和 Runtime 管道租约体系替代。该变化是已经批准的一次性破坏性迁移，不属于待修复缺陷。

修改要求：不恢复兼容接口和旧线协议；清理所有活动源码残留，在迁移文档中提供旧能力到新架构的对应关系。唯一兼容面仍限于 CLI v3 用户 JSON 的别名、扩展和 `composites`。

## 5. 修改清单

### 5.1 统一生命周期

- [ ] 新增 `WebRuntimeProgramHostState`。
- [ ] 状态统一为 `Created / Starting / Running / Stopping / Stopped / Faulted / Disposed`。
- [ ] `ActivateAsync` 和 `StopAsync` 使用同一生命周期锁。
- [ ] CommandTarget 的 initialize/stop 改为调用 Host。
- [ ] 重复启动、重复停止返回幂等结果。
- [ ] Dispose 后拒绝启动和执行请求。

### 5.2 初始化回滚

- [ ] Registry 记录成功初始化的 Program。
- [ ] 初始化失败时按反向顺序停止已初始化项。
- [ ] 每个回滚操作独立捕获异常。
- [ ] 回滚结束后清空初始化登记。
- [ ] 汇总初始化错误和回滚错误。
- [ ] Host 状态设置为 `Faulted`。

### 5.3 可靠停止

- [ ] 停止开始后禁止新的 Program 执行请求。
- [ ] 取消所有活动执行。
- [ ] 在规定超时内等待活动执行结束。
- [ ] 逐个停止所有已初始化 Program。
- [ ] 单个停止失败不能中断后续清理。
- [ ] 最后统一撤销登记。
- [ ] 返回成功、带错误完成或超时状态。
- [ ] 与 Runtime 总体安全退出倒计时对接。

### 5.4 Ambient 输入控制器

- [ ] 使用单一状态机替换 `_started / _stopped`。
- [ ] 支持重复 `StartAsync -> StopAsync -> StartAsync`。
- [ ] 每次启动创建新的 CTS 和 RTask。
- [ ] 鼠标、键盘任务分别记录状态。
- [ ] pulse 异常转为 `Faulted`。
- [ ] 异常通过 Runtime 监视点发布。
- [ ] `DisposeAsync` 改为幂等。
- [ ] Dispose 后禁止再次启动。
- [ ] CLI 返回真实状态。

### 5.5 旧 API 清理与新架构替代

- [x] 删除 `IWebRuntimeControl` 兼容接口。
- [x] 会话能力迁移到 `IWebRuntimeSession`。
- [x] 线协议迁移到 `RuntimeDiagnosticFrame`。
- [x] 业务执行迁移到 `IWebRuntimeBusinessProgram` 与 Program Host/Registry。
- [x] 管道申请、解析和释放迁移到 Runtime 管道租约体系。
- [x] 活动源码不保留旧 Envelope、旧 DTO 或旧管道消息入口。
