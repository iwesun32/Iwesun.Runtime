# 完整改改方案

> 状态说明：本文是跨阶段整改路线图，其中的未勾选项目不能直接解释为 1.0.19 发布缺陷。当前 WebView2 已交付能力、构建验证和仍待实机验证范围见 WEBVIEW2_RELEASE_STATUS.md。

## 1. 目的

本方案统一整改 Runtime Diagnostics、CLI 和 WebView2 公共库中已经通过实测确认的问题，避免继续由多个宿主或使用方分别修改同一套基础设施。

整改目标：

- 程序身份不再被旧 JSON 或错误路径覆盖；
- 四个宿主拥有稳定、独立的 CLI 主管道；
- 安全退出不存在监视器等待自身的闭环；
- CLI 路由、单点监视、断点上下文和复合命令行为完整一致；
- WebView2 生命周期、初始化回滚、停止清理和 Ambient 输入状态可靠；
- 所有变更由 Runtime 仓库统一实现、测试和发布。

## 2. 整改所有权和冻结规则

### 2.1 唯一实施方

以下代码的最终整改只允许在 `D:\Git Space\Runtime` 完成：

- `Iwesun.Runtime.Diagnostics`；
- `Iwesun.Runtime.Cli`；
- `Iwesun.Runtime.Data`；
- `Iwesun.Runtime.WebView2`；
- `Iwesun.Runtime.SampleHost`；
- Runtime 文档、发布目录和 Setup 工程。

### 2.2 WebView2 使用方的职责

WebView2 使用方以后只提供：

- 问题现象；
- 最小复现步骤；
- 日志、调用参数和返回 frame；
- 预期行为；
- 设计审查意见；
- 新版 DLL 的联调结果。

不得再直接修改 Runtime/WebView2 公共库源码、CLI catalog、协议模型或发布工程。

### 2.3 宿主允许的最小改动

宿主项目只允许：

- 引用 Runtime 发布的 DLL；
- 在主程序声明固定管道名和记录路径；
- 使用公开的 Start/Activate/Stop 接口；
- 注入业务监视点、断点和受管任务；
- 删除已经废止的临时兼容代码。

宿主不得复制 ConfigStore、管道服务器、退出协调器或 CLI 路由实现。

## 3. 已确认事实

### 3.1 已验证通过

- 四条独立 CLI 管道均可访问；
- 标准复合命令 `runtime.inspect` 成功；
- 用户复合命令 `diagnostics.quick-check` 成功；
- 断点启用、命中、查询和恢复链路可用；
- DList 扫描专用委托未发现重叠启用和静态并发污染；
- `identity-loss` 断点证明身份在最终归一化阶段丢失，不是 UI 解析问题；
- `BreakpointSnapshot` 已加入 `LastContext`，源码编译通过。

### 3.2 仍待整改

- `reflection.get` 路由和参数定义异常；
- 标准 CLI 缺少 output point 单点启用和禁用；
- 运行进程尚未验证 `breakpoint.list` 返回新版 `LastContext`；
- shutdown-watch 参与退出门槛，形成自等待闭环；
- Runtime 仍存在 JSON 配置文件链路；
- 审计当时识别的 WebView2 生命周期和异常清理问题进入本方案；1.0.19 当前状态及未完成的实机故障注入范围见 WEBVIEW2_RELEASE_STATUS.md。

## 4. 第一阶段：取消 Runtime 配置文件

### 4.1 最终配置模型

彻底停止读取、合并和写入 `diagnostic-switchboard.json`。

```text
源码声明：固定身份和可靠默认值
启动参数：唯一启动期临时覆盖
CLI 指令：当前进程内存状态
进程退出：恢复源码默认值
```

### 4.2 管道名决议

```text
--diag-pipe / --runtime-diagnostics-pipe
    >
Services.Start(...startupRuntimeDiagnosticsPipeName)
    >
DiagnosticPipePrefixAttribute
    >
编译默认值
```

### 4.3 记录文件决议

```text
--diag-file / --runtime-diagnostics-file
    >
Services.Start(...startupRuntimeDiagnosticsFilePath)
    >
DiagnosticFileOutputAttribute
    >
编译默认值
```

### 4.4 实施清单

- [ ] 新增只读 `RuntimeDiagnosticStartupOptions`。
- [ ] DI 阶段完成源码声明和命令行参数决议。
- [ ] Monitor 直接接收最终管道名。
- [ ] 文件记录器直接接收最终路径、格式和模式。
- [ ] 删除 ConfigStore 文件读取、回写和 reload/save 语义。
- [ ] 旧 JSON 存在时完全忽略，不自动删除。
- [ ] 删除或废止所有 `persist` 参数。
- [ ] Snapshot 增加最终值来源字段。
- [ ] 启动完成后禁止运行期修改主管道和主记录路径。

### 4.5 宿主临时代码清理

四个宿主当前“启动前强制写 JSON”只保留到本阶段验证完成。新版 Runtime 生效后，宿主删除该逻辑，仅保留主程序源码声明。

## 5. 第二阶段：修复安全退出

### 5.1 根因

`shutdown-watch` 是退出协调基础设施，但以普通受管任务登记并进入 `CanExit` 统计，导致它等待登记表清空，而登记表又等待它自己退出。

### 5.2 实施清单

- [ ] 给受管登记增加 `BlocksShutdown` 或等价角色字段。
- [ ] 普通进程、线程、任务默认阻止退出。
- [ ] shutdown-watch、指令分发器等协调基础设施不进入业务退出门槛。
- [ ] `EvaluateShutdownStatus` 只返回真正阻止退出的单元。
- [ ] 主控仍能观察基础设施状态，但不把它计入 `CanExit`。
- [ ] 业务登记清空后，shutdown-watch 自行销户并退出。
- [ ] 超时返回 124，正常返回 0。
- [ ] 重复 shutdown 请求保持幂等。

## 6. 第三阶段：修复 CLI

### 6.1 reflection.get

- [ ] 目标使用 `{target}` 路由模板。
- [ ] `target` 只作为路由参数，不重复发送为业务位置参数。
- [ ] `member` 正确传递给 Reflection target。
- [ ] 支持位置形式和命名形式。
- [ ] 未注册目标返回明确代码和可用目标提示。

### 6.2 output point 单点控制

新增标准命令：

```text
switchboard.point.list
switchboard.point.enable <id>
switchboard.point.disable <id>
```

- [ ] list 支持 id、section、category、source、kind 和 text 过滤。
- [ ] enable/disable 只修改当前进程内存状态。
- [ ] 不存在的 ID 返回 `OUTPUT_POINT_NOT_FOUND`。
- [ ] 文档说明 Global、Section、Point、输出通道四级门控。
- [ ] 验证 Seen、Suppressed、Published 的变化符合开关状态。

### 6.3 断点上下文

- [x] `BreakpointSnapshot` 增加 `LastContext`。
- [x] Snapshot 投影写入内部保存的上下文。
- [ ] 新 Debug 宿主加载新版 DLL。
- [ ] 启用 `identity-loss` 并命中一次。
- [ ] `breakpoint.list` 返回完整 `LastContext`。
- [ ] 显式 resume 后关闭断点，避免重复暂停。
- [ ] Release 继续不装配断点实现。

### 6.4 复合命令回归

- [ ] 标准 `runtime.inspect` 保持一次 batch 发送。
- [ ] 用户 `diagnostics.quick-check` 保持一次 batch 发送。
- [ ] 用户增量 alias、add、extend、replace、disable 不回退。
- [ ] 复合命令不引入 workflow 语义。

## 7. 第四阶段：WebView2 生命周期整改

### 7.1 Host 状态机

新增：

```text
Created -> Starting -> Running -> Stopping -> Stopped
                    -> Faulted
任意可释放状态 -> Disposed
```

- [ ] Activate、Stop、Dispose 使用同一生命周期锁。
- [ ] CommandTarget 的 initialize/stop 统一调用 Host。
- [ ] Registry 生命周期方法收紧为内部接口。
- [ ] 重复启动和停止保持幂等。
- [ ] Dispose 后拒绝执行。

### 7.2 初始化失败回滚

- [ ] 记录成功初始化的 Program 顺序。
- [ ] 后续失败时反向 Stop。
- [ ] 单项回滚失败不阻断其他项。
- [ ] 汇总初始化错误和回滚错误。
- [ ] 清空登记和活动执行。
- [ ] Host 状态转为 Faulted。

### 7.3 可靠停止

- [ ] 停止开始后拒绝新执行。
- [ ] 取消所有活动执行。
- [ ] 限时等待执行结束。
- [ ] 尝试停止全部已初始化 Program。
- [ ] 单项失败不阻断后续清理。
- [ ] 最终状态区分 Stopped、StoppedWithErrors、TimedOut。
- [ ] 无论错误如何都撤销登记。

### 7.4 Ambient 输入

- [ ] 用单一状态机替换 `_started/_stopped`。
- [ ] 支持 Start、Stop、再次 Start。
- [ ] 每次启动创建新的 CTS 和 RTask。
- [ ] 鼠标、键盘任务分别记录状态和最后错误。
- [ ] pulse 异常转为 Faulted 并发布监视事件。
- [ ] Stop 和 Dispose 幂等。
- [ ] Dispose 后拒绝启动。
- [ ] CLI 返回实际状态，不固定返回 Running。

### 7.5 旧 API 清理

`IWebRuntimeControl` 已被批准作为一次性破坏性迁移删除，不恢复兼容层。

- [x] 删除 `IWebRuntimeControl`。
- [x] 会话能力迁移到 `IWebRuntimeSession`。
- [x] 线协议迁移到 `RuntimeDiagnosticFrame`。
- [x] 业务执行迁移到 `IWebRuntimeBusinessProgram` 与 Program Host/Registry。
- [ ] 补充旧能力到新接口的迁移对照表。
- [ ] 确认活动源码不存在旧 Envelope、DTO 和管道入口。
