# SampleHost 与 CLI 全功能实机验收设计

## 1. 目标

扩展现有 `Iwesun.Runtime.SampleHost`，在不改变其三条定时循环总体结构的前提下，持续生成随机数并注入 Runtime 的诊断、状态和执行管理能力。由 `Iwesun.Runtime.FunctionalTests` 启动真实 SampleHost，再通过独立 CLI 进程逐项验证完整功能，最后使用 `safe-shutdown` 安全退出宿主并生成结构化报告。

宿主默认持续运行，不按固定次数自动退出。测试完成或失败收尾时均优先通过 CLI 安全退出。

## 2. 方案边界

### 2.1 实现位置

- SampleHost 负责提供真实、持续变化的业务状态和注入点。
- FunctionalTests 负责编排宿主进程、CLI 命令、断言、超时和报告。
- Runtime Diagnostics 与 CLI 只在发现真实功能缺陷时修改；测试不得依赖未定义的副作用。
- Runtime 实现改动只落在本仓库，DDNS Snap 不承载本设计的实现。

### 2.2 不做事项

- 不创建第二个重复的样板宿主。
- 不使用系统级命名 MMF 或命名 Semaphore 保存断点状态。
- 不用 CLI 连接断开隐式恢复断点。
- 不用固定延迟猜测断点是否已经进入等待。
- 不扩大反射白名单到未明确列出的成员。

## 3. SampleHost 随机数运行模型

Worker 循环每次唤醒生成一个有界整数随机数，并更新线程安全的随机状态对象。状态至少包含：

- `CurrentValue`：当前随机数。
- `PreviousValue`：上一次随机数。
- `MinimumValue`：运行期最小值。
- `MaximumValue`：运行期最大值。
- `SampleCount`：累计生成次数。
- `UpdatedAt`：最近更新时间。

随机状态通过只读快照对外暴露。测试只断言范围、计数增长、时间更新和跨周期变化，不断言具体随机序列，避免随机性造成不稳定测试。

## 4. 功能注入

### 4.1 输出与监视

- 每次生成随机数后发布结构化输出点，负载包含随机状态快照和当前迭代。
- 注册随机状态 watch point，并通过 `RuntimeInjector.Watch` 更新可观察值。
- 保持默认静默策略；测试通过 CLI 显式启用需要观察的 section、point、pipe 或 file 输出。

### 4.2 对象访问

通过 `RuntimeInjector.Data` 注册随机状态目标：

- 只读成员：当前值、前值、最小值、最大值、计数、更新时间和快照。
- 可调用成员：仅允许无副作用的 `Snapshot`。
- 不开放广泛写入或任意方法调用。

现有 `sample.host` 状态目标继续承担暂停、恢复、重置和故障注入的受控验证。

### 4.3 普通断点

至少设置两类普通断点：

- 编译初始启用断点：无需 CLI enable 即能进入等待，用于验证程序集反射初始值。
- 编译初始禁止断点：默认不得阻塞；CLI enable 后生效，CLI disable 后再次不阻塞。

断点命中后必须先通过 `bp.snapshot` 观察 `IsWaiting=true`，再使用显式 `bp.resume` 恢复。连续快照及 CLI 断开不得改变等待状态。

### 4.4 数值数据断点

随机数用于验证：

- 单值阈值：`gt`、`lt`。
- 区间：`between`、`outside`。
- 双值比较：`eq2`、`ne2`、`ge2`、`le2`。
- 差值：`delta-le3`、`delta-gt3`。

测试动态设置规则后，等待符合条件的随机样本。为保证有限时间内可验证，测试可以通过受控对象方法触发指定验证样本，但真实定时随机循环必须持续运行并有独立增长断言。

### 4.5 事件、线程、任务与状态

- 随机状态更新触发可挂接事件，用于 `hook.enable`、事件观察和 `hook.disable`。
- 三条已有循环继续登记静态线程和静态任务。
- 每次随机批次登记动态任务并完成收尾，验证动态任务可见且无残留。
- 验证全局状态、单元状态、状态历史和允许的状态迁移。

### 4.6 文件与 RuntimeRoot

- 验证诊断文件最终路径可从 RuntimeRoot 查询。
- 验证文件记录状态、启动、停止和按文件控制。
- 测试结束后恢复静默状态；安全退出前完成文件刷新和状态快照。

## 5. CLI 全功能验收清单

FunctionalTests 使用编译后的 CLI DLL 和 v2 配置，对真实 SampleHost 管道执行：

1. 宿主与目标：`host.list`、`host.info`、`host.events`。
2. 开关板：全局、pipe、file、section、output point 的查询与动态开关。
3. RuntimeRoot：最终文件路径与描述查询。
4. 登记表：watch points、breakpoints、hooks 和全部登记项。
5. 对象访问：允许成员读取、快照调用、受控状态修改；禁止成员必须失败。
6. 普通断点：初始启用、初始禁止、动态 enable/disable、等待、显式 resume、resume-all。
7. 数值断点：静态谓词、阈值规则、动态切换、命中、未命中、清除规则。
8. Hook：列表、启用、事件可见、禁止后不再产生新 hook 结果。
9. 执行管理：静态/动态线程与任务快照、心跳、完成态和清理。
10. 状态：当前状态、历史、迁移和非法迁移失败路径。
11. 文件记录：状态、启用、禁止、文件级控制和实际落盘。
12. 连接语义：只读 CLI 短连接和断开不恢复或改变断点。
13. 安全退出：`safe-shutdown` 先恢复等待断点，再请求 graceful shutdown；以目标进程退出和退出码为最终证据。

## 6. 测试编排与等待策略

1. Debug 构建 SampleHost、CLI 和 FunctionalTests。
2. 启动 SampleHost，捕获 stdout、stderr、进程 ID 和诊断管道名。
3. 轮询最小宿主命令，确认管道已可用。
4. 先验证编译初始值，再执行任何动态修改。
5. 按清单执行 CLI 命令，每条记录命令、退出码、响应状态和关键数据。
6. 所有异步状态使用条件轮询和明确超时；断点恢复必须在观察到 `IsWaiting=true` 后执行。
7. 任一失败都记录当前断点、线程、任务、状态和宿主 stderr 快照。
8. 在 `finally` 等价收尾路径调用 `safe-shutdown`；仅当 CLI 已不可达且进程无法自行退出时使用进程终止兜底。

## 7. 报告与验收标准

报告输出 JSON，至少包含：

- 构建结果和警告/错误数量。
- SampleHost 启动、随机循环增长和安全退出证据。
- 每个 CLI 功能项的命令、结果、耗时和断言。
- 断点初始值、动态控制、等待与恢复证据。
- 数据断点每类谓词的命中和未命中证据。
- 文件路径、文件存在性和内容标记。
- 失败时的 stdout、stderr、退出码和关键快照。

完成标准：

- 清单全部通过且失败列表为空。
- SampleHost 随机计数至少跨多个定时周期增长。
- CLI 断开不改变断点状态。
- 所有命中的断点均显式恢复。
- `safe-shutdown` 后宿主在超时内退出，退出码为 0。
- 无遗留 SampleHost、CLI 或 FunctionalTests 调试进程。

## 8. 风险与处理

- 随机样本迟迟不满足断点条件：使用宽概率条件并设置总超时；需要确定性覆盖时使用受控验证样本，不伪造定时随机增长。
- 恢复命令抢跑：先轮询 `IsWaiting`，再恢复。
- 安全退出与新断点竞态：退出前禁止断点，或循环执行显式 resume-all 直到无等待项，再请求关闭。
- CLI `host.stop` 关闭连接早于响应：同时检查响应和目标进程退出；进程退出是最终证据。
- 文件测试污染工作区：使用测试专属运行目录和唯一文件名，不覆盖用户文件。
