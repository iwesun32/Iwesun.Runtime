# 注入器静态方案（旧方案保留）

> 状态：REFERENCE（保留）  
> 最后更新：2026-07-10  
> 适用范围：当前已上线的静态入口与兼容路径

## 1. 方案定位

该方案是历史与当前兼容路径，核心特征是：

1. 业务代码通过静态入口调用（如 `RuntimeOutput.*`、`RuntimeInjector.*`）。
2. 诊断路由由静态开关板（`DiagnosticSwitchboard`）统一处理。
3. 断点桥接由静态 helper（`BreakpointHelper`）持有实例引用。
4. 执行/登记上下文通过静态注入上下文（`RuntimeInjectionContext`）提供。

## 2. 优点

1. 接入成本低，调用简单。
2. 与现有项目代码兼容性好。
3. 调试与排查链路成熟，改动面小。

## 3. 风险与边界

1. 多实例并存时，静态槽位可能出现“后写覆盖前写”风险。
2. 对象实例语义（`this`）无法直接在静态槽中精细表达。
3. 注册/解绑如果分散在多个调用点，维护成本高。

## 4. 适用场景

1. 单进程、单运行时实例为主的宿主。
2. 以快速接入和稳定兼容为优先的阶段。
3. 尚未切换对象级缓冲池治理的模块。

## 5. 与动态方案关系

1. 静态方案不删除，作为兼容 facade 与回退基线保留。
2. 动态方案落地后，静态入口应仅做转发，不再直接持有对象级状态。
3. 迁移遵循“先可并行，再切默认”的策略，避免一次性破坏性改造。
